## 2. Genealogia probelor și referințele de arhivă

Din 37 PR-uri rezultă **22 de commituri distincte**; **20** aparțin unui lanț Git normativ și documentar continuu, #320→#353, cu fiecare `base_sha` egal cu `head_sha` al etapei primare precedente. **Aceasta este conservarea efectivă înainte de cleanup.** Un PR închis **nu șterge** commitul, branch-ul sau comentariile; refurile de arhivă suplimentare păstrează reachability chiar dacă un branch original ar fi reorganizat ulterior. Referințele sunt branch-uri Git cu SHA verificat, nu taguri semnate și nici garanții legale de imuabilitate împotriva unui administrator GitHub; este interzisă actualizarea ori ștergerea lor în acest flux.

Inventarul machine-readable [p9.0.8-ci-artifact-inventory.json](p9.0.8-ci-artifact-inventory.json) leagă cele **22 de HEAD-uri probatorii distincte** de rulările PR observate pe SHA-ul final și mapează separat cele 15 PR-uri CI-only prin identitate exactă de HEAD. Pentru celelalte HEAD-uri, toate rulările returnate la audit au fost finalizate cu `success`.

Artefactele GitHub Actions sunt tratate separat de conservarea Git. Au fost observate **8 artefacte probatorii istorice** pe head-urile primare (unul pentru #310 și șapte instanțe ale pilotului de acces oficial în lanțul #343–#353, incluzând rularea inițială #38894085292) și **2 artefacte P9.0.8** ale gate-ului de retenție. Fiecare are ID, digest SHA-256, stare de expirare și termen de retenție în registru. Aceste obiecte sunt marcate `TRANSIENT_ACTIONS_ARTIFACT` și **nu sunt folosite ca dovadă de conservare permanentă**: rezultatul pilotului relevant este păstrat în Git prin `docs/p9.0.7.2.10.2.1-access-evidence.json`, iar cele trei refuri `archive/p9.0.8-...` rămân substratul de reachability pentru corpusul versionat.

Limită API consemnată: lista de workflow-uri provine din rulările pull-request asociate SHA-ului final returnate de conector pe prima pagină; inventarul artefactelor a fost verificat pentru workflow-urile probatorii P9 și pentru gate-ul P9.0.8, fără a pretinde enumerarea exhaustivă a eventualelor artefacte auxiliare produse de workflow-uri generice. Această limită nu afectează conservarea, deoarece niciun artefact Actions nu este clasificat drept substrat unic de păstrare.
