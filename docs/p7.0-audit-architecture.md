Data: 2026-10-10. Baseline auditat: `478aba20fef7238808da8d16b894f1069d464224`.
Branch: `web/p7.0-audit-architecture`. Acest document nu închide P7.0 înainte de verificările pe HEAD exact și auditul post-merge.

## 1. Inventar și limite

Aplicație statică ES modules, Leaflet 1.9.4, fără framework și fără backend. `app.js` orchestrează selecția, filtrele, încărcarea și URL-ul. Modulele existente: presentation, search, filters, tree, hierarchy validation, URL state, explorer shell, mobile UI, info panel, advanced navigation și fit RO+MD.

`index.html` încarcă nouă foi CSS proprii: `style.css`, shell, P5.3 și șase fișiere P6. Stilurile pentru aceleași componente sunt redefinite succesiv. Fișierul de bază încă include prezentări mai vechi ale arborelui și layoutului. Această fragmentare justifică consolidarea; nu justifică eliminarea oarbă a regulilor care asigură focus, forced-colors sau remedierile P6.4.3.

Nu există `AGENTS.md` în arborele Git inspectat. Nu erau PR-uri deschise la începutul auditului. Branch-urile vechi de prototip și de candidate ACTUAL nu sunt utilizate drept baseline frontend.

Corpusurile ACTUAL/P2, ISTORIC/PROPUNERI, geometria EPSG:4326, identitățile, snapshoturile, manifestele și fingerprinturile sunt în afara modificărilor P7. Numai rădăcinile România/Moldova sunt bifate implicit. Selecția, extinderea, checkboxul și filtrele rămân acțiuni independente.

## 3. Referințe de interacțiune

[OpenStreetMap](https://www.openstreetmap.org/) este referința pentru separarea căutării/panoului lateral de hartă și comenzi cartografice.
[OSM-Boundaries](https://osm-boundaries.com/map) este referința pentru explorarea ierarhică și diferențierea selecției de geometrie.

Se studiază interacțiunea și organizarea vizuală; nu se copiază CSS, cod sau date. OSM-Boundaries avertizează că pagina nu este optimizată pentru mobil: această limitare nu este preluată. Ierarhia noastră rămâne cea validată administrativ/statistic, nu cea dedusă geometric.

## 4. Arhitectură țintă și ownership

`app.js` rămâne composition root. Refactorizarea extrage responsabilități, fără introducerea unui framework sau a unei a doua aplicații.

- `atlas-layout.mjs`: unica sursă pentru dimensiunile efective, breakpoint și orientare; subscriptions și cleanup.
- `atlas-preview.mjs`: reducer pentru mode/orientation, dimensiuni logice, bară SVG și revenire explicită la Automat.
- `atlas-panels.mjs`: registru de panouri, activePanel, open/close, Escape, activator și focus return.
- `atlas-navigation.mjs`: rail desktop/tabletă și navigare mobilă cu overflow „Mai multe”; etichete accesibile.
- Modulele search/filters/tree/advanced/info rămân proprietarii conținutului și primesc callbacks către serviciile existente.
- `atlas-map-controls.mjs`: montarea grupului Leaflet, locație adaptivă și măsurarea spațiului disponibil.
- CSS final: tokens/base, shell/layout, navigation/panels, tree/search/filters, map/details/preview; fără fișiere numite după hotfixuri.

Starea semantică publicabilă este capturată exclusiv prin `atlas-url-state.mjs`. Starea de UI include activePanel, focus origin, dimensiune panou și sheet. Starea preview include mode=auto|desktop|tablet|phone și orientation=portrait|landscape; este efemeră și nu intră în URL-ul cartografic.

Panel manager-ul nu devine un al doilea store de selecție/geometrii. Adaptoarele panourilor nu fac fetch propriu al catalogului sau al geometriilor.

## 5. Preview: comparație și alegere

| Alternativă | Beneficiu | Cost/risc | Verdict |
| --- | --- | --- | --- |
| iframe al aplicației | Media queries native în viewport izolat | A doua hartă, fetch repetat, focus/History separat, recursie | Respins pentru P7 |
| Transformarea întregii aplicații | Dimensiuni logice complete | Targets micșorate pe telefon; media queries încă urmăresc fereastra reală | Nu este suficient singură |
| Root dimensionat + container queries + layout adapter | O hartă/cache/URL; praguri pe dimensiunea logică | Migrare coerentă a tuturor consumatorilor breakpoint | Alegerea țintă |
| Doar clase desktop/tablet/phone | Implementare mică | Nu reproduce dimensiunile; poate diverge de modul auto | Respins ca mecanism unic |

P7.1 introduce root-ul de viewport și migrează sursa breakpoint în același PR, înaintea panourilor P7.2. CSS responsive este consolidat pe parcurs, cu eliminarea regulilor supersedate verificată prin browser.

Preseturi inițiale: desktop 1440×900, tabletă 768×1024, telefon 390×844. Rotire schimbă dimensiunile logice; în auto este dezactivată. Root-ul auto folosește spațiul disponibil real și safe-area. Leaflet primește invalidateSize după stabilizarea layoutului, cu pan:false.

Pe un telefon, preview desktop poate depăși suprafața fizică. Soluția trebuie să păstreze bara și butonul Automat în afara canvasului logic și să permită scroll/pan controlat al cadrului. Reducerea vizuală opțională nu poate fi singura cale de interacțiune, deoarece micșorează țintele tactile. Dacă prototipul nu trece hit-test/keyboard/URL și măsurarea requests, se revizuiește înainte de merge; nu se prezintă simularea drept dispozitiv fizic.

## 6. Panouri, focus și responsive

Desktop ≥900px: rail 56px, panel contextual redimensionabil cu limite adaptate spațiului disponibil. Harta folosește restul spațiului; închiderea panoului eliberează lățimea.
Tabletă 600–899px: rail compact și panel suprapus cu lățime limitată; cardul de selecție și comenzile hărții au sloturi rezervate.
Telefon <600px și landscape cu înălțime redusă: dock cu Entități/Căutare/Mai multe; restul acțiunilor într-un meniu accesibil. Nu se afișează opt iconuri verticale.

Un singur panou principal activ. Cardul entității este context de selecție separat; pe viewporturi mici, panelul principal primește prioritate spațială și sheet-ul se minimizează fără schimbarea selecției.

Activare: închide panelul anterior, anulează activități efemere, aplică hidden/inert sincron, focalizează titlul/controlul util. Escape are ordine documentată: popup căutare → meniu secundar → panel principal; cardul nu pierde automat selecția. La închidere, focus revine la activatorul vizibil sau fallback din navigare.

Focus trap se aplică numai prezentării modal; panelul desktop ne-modal nu blochează harta. Resize are pointer capture și taste Arrow/Home/End. Toate comenzile interactive au ținte efective ≥44px, focus-visible, nume accesibil și forced-colors.

## 7. Arbore, accesibilitate și performanță

P7.3 definește modelul flattened visible rows derivat exclusiv din nodeById/rootIds și openIds. Rândurile vizibile sunt virtualizate cu overscan, chei entity_id și păstrarea rândului focalizat. Nu se mută focusul către un nod eliminat din DOM.

Nu se adaugă role=tree fără contract complet de navigare Arrow/Home/End și aria-level/expanded/posinset/setsize. Checkboxul, disclosure și selectarea rămân trei controale distincte. Scroll către entitatea selectată nu modifică checkboxul.

Închiderea ramurilor eliberează rândurile virtuale; selecția URL poate deschide calea fără randarea tuturor celor 5848 noduri. Metadatele oficiale rămân în card, nu în meniul de navigare.

Se măsoară cold și warm separat, requests pe geometrie, noduri DOM, long tasks, FCP și timpul până la catalog/hartă utilizabilă. Nu se deduce performanță mobilă din resize-ul unei pagini deja încărcate. Testele mobile cold cer navigări separate, cache controlat și raportarea condițiilor; niciun scor nu se inventează.
