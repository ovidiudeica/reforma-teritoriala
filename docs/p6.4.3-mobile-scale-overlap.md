# P6.4.3 — Hotfix: scala Leaflet nu acoperă bara cu patru iconuri

**Baseline exact:** `main bfef878859fffa54937ce2b398475b0fbac6f349` (P6.4.2 integrat). Branch izolat `web/p6.4.3-mobile-scale-control-overlap`.

## Defect confirmat prin capturi Chrome live

La telefon portret 390×844, landscape 844×390 și tabletă 768×1024, scala Leaflet `300 km` apărea la `x≈10, y≈163`, în timp ce butonul de încadrare RO+MD ocupa `x≈12–56, y≈160–204`. Rectangulele se intersectau, iar textul scalei acoperea vizual iconul de încadrare, deși clickul central continua să ajungă la buton. Testul anterior P6.4.2 verifica targetul butonului OSM, dar nu **intersecția** scalei cu întregul grup. Pe desktop 1440×900, după navigarea/relayout corect, scala era la baza hărții fără această suprapunere.

Cauza: regula mobilă P6.2 `#atlas-main .leaflet-bottom.leaflet-left{bottom:auto;top:103px}` fixa scala în colțul stâng, unde P6.4.1 a integrat ulterior controalele în Leaflet.

## Remediere și regresie

- Păstrăm scala în partea **superioară-dreaptă a hărții pe lățimi sub 900px**, imediat sub creditarea OSM, prin `left:auto;right:10px` pe containerul scalei; păstrăm `top:103px`. Eliminăm margin-left vechi.
- Nu mutăm/alterăm butoanele `+ / − / RO+MD / OSM`, harta, fundalul OSM ori contractul URL.
- Extindem gate-ul Chrome/CDP P6.4.2 cu două condiții noi pentru cele opt viewporturi: **centrul fiecărui buton este neobturat** și **dreptunghiul scalei nu intersectează deloc grupul celor patru controale**. Aceste condiții ar fi prins regresia înainte de merge.
- Validăm telefon portret și landscape, tabletă 768×1024, pragurile 899/900 și desktop 1440×900, fundalul OSM independent și pagina publicată după merge.

## Criterii de integrare

PR separat, required checks + CodeQL, verificare exact HEAD SHA, fără bypass; după merge, Pages live, control al scalei/iconurilor, 123/123 GeoJSON și toate resursele frontend byte-identice. Corpusurile ACTUAL/P2, ISTORIC/PROPUNERI, SIRUTA/CUATM, manifestele și geometriile EPSG:4326 rămân **neschimbate**.

**P6.5 release closure [PR #281](https://github.com/ovidiudeica/reforma-teritoriala/pull/281) este blocată** până la integrarea și validarea acestui hotfix; apoi documentația P6.5 trebuie să includă și P6.4.3.
