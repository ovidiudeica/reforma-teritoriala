# P9.0.9 — Nistrenia vizibilă în Entități (grupare OSM, fără promovare juridică)

## Defect confirmat în P9.0.7.2.16
Cele 85 de roluri cartografice validate erau afișate doar în **Filtre → Roluri cartografice OSM**, într-un `<details>` închis implicit. Nici un nod „Nistrenia” nu era prezent în navigarea principală a utilizatorului. Această prezentare nu îndeplinea intenția de a avea Nistrenia și subdiviziunile ei accesibile vizibil în website.

## Remediere
- În **Entități**, intrarea vizibilă **„Nistrenia · OSM”**, în același rând cu comanda de resetare a geometriilor, deschide la cerere un catalog suprapus. Această prezentare nu reduce înălțimea arborelui virtual și nu creează root, entitate CUATM ori geometrie nouă.
- Prin activarea comenzii sunt afișate exact șapte grupări ale relațiilor-părinte OSM: Camenca (13), Rîbnița (23), Dubăsari (10), Grigoriopol (16), Tiraspol (3), Slobozia (16), Bender (4); total **85 ID-uri ACTUAL unice**.
- „Arată” pentru fiecare ID reutilizează selectarea ACTUAL existentă; „Arată toate” activează în aceeași stare `visibleEntityIds` cele 85 de geometrii, iar harta este încadrată pe bounding box-ul lor, **fără a construi vreun poligon nou**.
- Grupările folosesc `geometric_osm_parent_id` din dosarul cartografic P9.0.7.2.15, nu `claimed_de_facto_parent_id_separate`. Un părinte geometric **nu** devine părinte administrativ legal.
- Rădăcina `OSM relation/65335` este oferită doar ca link de proveniență; ea **nu** are contur ACTUAL propriu. „Arată cele 85” arată poligoanele reutilizate, nu pretinde un contur agregat identic cu relația 65335.
- Deosebim Bender `osm-r12463379` de `osm-r9581354`, plus orice alte nume identice, prin ID și rol OSM.
- Datele noi din `public/data/p909-nistrenia-osm-navigation.json` sunt doar index/cartografie, cu generator determinist `scripts/process/build-p909-nistrenia-menu.mjs --check` și validare runtime fail-closed.

## Gate-uri obligatorii
1. Build determinist cu `--check`, validator și regresii de mutație P9.0.9.
2. Chromium pe desktop și mobil: intrarea „Nistrenia · OSM” vizibilă în Entități; 7/85; zoom/selectare existentă; lipsă overflow; fără resurse GeoJSON P9 noi.
3. Suitele și branch protection existente, fără ocolire; PR separat înainte de orice integrare.
4. După un eventual merge: audit pe `main`, CI post-merge și publicarea GitHub Pages.

## Remediere P9.0.9.1 — protecția arborelui virtual

Primul prototip adăuga un panou de 44px deasupra arborelui și a produs un eșec real în regresia P7.3 privind țintele tactile de 44px în viewporturi compacte. Nu s-a slăbit gate-ul P7.3: controlul Nistrenia se află acum în același rând cu „Resetează geometriile”, iar catalogul se deschide în overlay, fără modificarea dimensiunii arborelui RO+MD. Se verifică din nou integral browser QA și accesibilitatea P7.3 înainte de merge.

**P9.0.9.2 — P7.2:** Testul rutelor contextuale P7.2 a demonstrat că secțiunea Entități trebuie să păstreze `position:static`. Catalogul Nistrenia este acum ancorat într-un wrapper relativ al controlului din bara de comenzi; secțiunea Entități și controllerul comun nu-și schimbă proprietatea `position`. Contractele P7.2 și P7.3 rămân neschimbate și sunt rerulate integral.
