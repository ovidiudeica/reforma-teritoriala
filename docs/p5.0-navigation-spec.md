# P5.0 — Specificația navigării OSM-Boundaries-inspired (RO+MD)

**Status:** contract UX pentru evaluare, nu schimbare a interfeței publice. Issue [#263](https://github.com/ovidiudeica/reforma-teritoriala/issues/263). Prototip: [prototypes/p5-navigation/index.html](../prototypes/p5-navigation/index.html). Audit: [p5.0-navigation-ux-audit.md](p5.0-navigation-ux-audit.md).

## Contractul arborilor

Sursa unică este arborele public actual-consolidated-hierarchy-v1 (exact 5.848 noduri, două state). Nu se derivează noi relații de apartenență din intersecții de poligoane, BBOX sau din admin_level OSM. Ordinea copiilor rămâne cea din child_ids oficial.

Fiecare rând are controale independente:

1. **▸ / ▾:** extinde sau restrânge copiii; nu selectează și nu încarcă poligonul.
2. **Checkbox:** preferință individuală de vizibilitate; nu selectează și nu modifică filtrele globale. Un filtru global poate ascunde totuși limita; checkbox bifat nu suprascrie jurisdicția ori regulile de nivel.
3. **Badge:** stat, NUTS 1/2/3 în RO, nivel statistic 1/2/3 în MD sau tip administrativ. Rolurile consolidate primesc o singură identitate și un singur rând.
4. **Nume:** selectează identitatea, extinde toți strămoșii și aduce rândul în viewport. Selectarea poate exista și dacă geometria este ascunsă; detaliul spune explicit motivul.

Pentru prototip, **selecția este unică (0/1)**, cu bară de selecție. Selecția multiplă/pinning și operațiile batch din OSM-Boundaries sunt decizii de produs separate, nu se insinuează existența lor. Arborele creează DOM pentru copii la prima expandare (nu toate cele 5.848 noduri simultan).

## Căutare

Caută global, indiferent de filtre, în nume afișat, nume oficial, ID stabil, SIRUTA/CUATM (unde există), cod statistic, relation ID OSM și aliasuri. Normalizarea pentru diacritice nu alterează denumirea afișată. Ordonare: potrivire exactă, prefix, apoi substring; afișează contextul jurisdicției, tipului și identificatorului. Primele 24 de rezultate sunt disponibile, cu Enter pe primul rezultat și Escape pentru închidere; tasta / focalizează căutarea.

## Contractul filtrelor

- **Jurisdicție:** RO și MD, fiecare ON/OFF; niciun rezultat al căutării nu dispare, chiar dacă poligonul lui e ascuns.
- **Clase geometrice:** context, regional, local UAT, sector, localități componente și auxiliare; clasele se derivează prin geometryClass din aplicația curentă, fără clasificare duplicată.
- **Subtipuri:** identificate prin geometrySubtype; opțiunile ascunse într-un disclosure avansat; nu se convertesc în clasificare juridică nouă.
- **Niveluri statistice:** 1/2/3; etichetele NUTS sunt afișate pentru entitățile RO, nu atribuite entităților MD.
- **Limite separate:** 18 geometrii statistice fără duplicare; vizibilitate condiționată simultan de nivel și toggle.
- **Combinație:** pentru cele 45 entități cu rol administrativ/de context și statistic, expresia este administrativa OR statistica; reactivarea unui rol face limita eligibilă. Checkbox-ul individual se aplică peste acest rezultat (AND).
- **Reset:** readuce toate filtrele la ON și reface preferințele individuale de vizibilitate; nu șterge selecția sau URL-ul.

## Harta și contractul datelor

Prototipul folosește Leaflet 1.9.4 ca aplicația actuală și cere prin HTTP fișierele EXISTENTE:

- public/data/actual-consolidated-tree.json
- public/data/actual-entities.json
- public/data/actual-geometry-chunks.json
- public/data/app-build-info.json
- public/geo/actual/<jurisdiction>-overview.geojson ori <jurisdiction>-statistical.geojson
- public/geo/actual/chunks/<jurisdiction>/<tier>/<root>.geojson pentru nivelurile local/detail.

Datele sunt numai citite. La selecție, se identifică tier-ul din metadata entității, se caută overview-root prin parent_catalog_id și se încarcă chunk-ul corespondent din manifest. Se extrage exclusiv feature.properties.entity_id egal cu ID-ul selectat, apoi poligonul original este evidențiat și încadrat pe hartă. Fără geometrie disponibilă: arată un status explicit, nu inventează poligon, nu modifică date și nu suprimă selecția. Cache-ul Promise per URL previne cereri duplicate. Harta de fundal OSM poate fi indisponibilă independent de datele geometrice.

**Important:** prototipul se concentrează pe *geometria selectată*, nu pe randarea simultană a tuturor straturilor vizibile. Pragurile și reîmprospătarea automată a întregii hărți după zoom rămân responsabilitatea aplicației de producție și vor fi migrate în P5.1+, păstrând P4. Acesta nu este un nou motor cartografic.

## Comportamentul mobile și accesibilitate

- Drawer se deschide din butonul de navigare, primește focusul pe căutare, se închide prin Escape, backdrop sau selectarea unei entități; focusul revine controlului de deschidere.
- Taburile au aria-selected, aria-controls și săgeți stânga/dreapta; toate acțiunile pentru rânduri au butoane/checkboxuri nativ tastabile. Se folosește **grup de controale**, nu se pretinde un widget ARIA tree cu tastatură completă.
- Sidebar poate fi redimensionat cu pointer și prin ArrowLeft/ArrowRight, Home resetează 410 px.
- Enter/click pe numele entității face selecția; detaliile folosesc textContent pentru conținut din date, niciodată HTML din câmpuri externe.
- URL folosește **e=<entity_id>** în prototip; popstate restabilește selecția. Nu sunt schimbate schema/codificarea URL de producție și nici interfața actuală.
- Focalizare vizibilă și preferring-reduced-motion respectat; fonturile și interacțiunile nu depind de o bibliotecă de UI externă.

## Scenarii de acceptare P5.0

Browserul real Chrome/CDP trebuie să demonstreze, pe snapshotul actual și fără fixture-uri artificiale:

1. Exact 5.848 entități și două rădăcini; arbore lazy și panou desktop fără overflow.
2. Căutare după cod oficial, nume normalizat fără diacritice, navigare și închidere.
3. Selecție RO și MD, URL-ul ID corect, poligonul selectat efectiv identic cu ID-ul solicitat.
4. Checkbox-ul ascunde/restabilește limita fără a șterge selecția, cu cache HTTP neschimbat.
5. OR administrativ/statistic pentru entitate coalesced și păstrarea selecției când ambii termeni sunt OFF.
6. Fetch dintr-un chunk local existent, fără a înlocui geometria cu o aproximație.
7. Mobil: drawer/tab/close și detalii contextuale, fără scroll orizontal.
8. Zero excepții JavaScript și erori de fetch ale aplicației; dovezi JSON + capturi desktop/mobil.

P5.0 nu modifică pagina index.html, app.js, style.css sau JavaScript-ul de producție. Toate controalele P4 continuă obligatoriu în CI. **P5.1 este implementarea integrată**, numai după validarea designului și a acestor criterii.
