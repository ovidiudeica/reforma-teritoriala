# P7.2 — coordonarea hărții, comenzilor și fișei

Baseline: `main` 5599ba5f619f4bf578ff435cb007598036b7c80a, după PR #286. Etapa rămâne deschisă până la validarea acestui hotfix pe GitHub Pages.

## Cauze și soluție

Shell-ul este singurul proprietar al poziționării hărții, panourilor, fișei și adnotărilor. Variabilele `--pane-space`, `--divider-space` și `--command-space` exprimă spațiul efectiv ocupat, inclusiv când panoul este închis. Regulile P5/P6 înlocuite au fost eliminate, nu compensate prin alte breakpointuri.

1. **Inițializare mobil → desktop.** Leaflet completează `position:relative` numai dacă poziția calculată nu este deja absolute/relative/fixed/sticky. Inițializarea mobilă omitea completarea, iar revenirea la desktop producea static și un strămoș greșit pentru comenzi. Harta are acum explicit relative pe desktop și absolute în layoutul mobil. [Sursa Leaflet 1.9.4](https://github.com/Leaflet/Leaflet/blob/v1.9.4/src/map/Map.js#L1097-L1100).
2. **Intersecții cu navigarea și fișa.** La 844×390, rail-ul intersecta grupul Leaflet cu 10px, deși hit-testul centrului trecea. La 900×768, un card lung intersecta comenzile cu 16px când panoul era deschis. Coloana rezervată de 65px și lățimea cardului calculată din spațiul real al hărții elimină ambele cauze. Ordinea și amplasarea laterală a celor patru comenzi sunt păstrate; P7.5 va decide amplasarea finală.
3. **Scală și atribuire acoperite.** Adnotările folosesc banda superioară, independentă de fișa extinsă: scala la începutul spațiului rezervat, atribuirea în dreapta. Limita inițială de 44px a scalei a fost reconsiderată după măsurarea depășirii etichetelor la zoom 0–19. Lățimea standard Leaflet de 100px permite text integral, fără distorsionarea CSS a distanțelor și fără intersecție cu atribuirea la 360px.
4. **Fișă compactă și focus.** Capturile au arătat că limita veche 30cqh tăia comenzile în landscape. Mânerul de 44px ocupă o coloană laterală comună tuturor stărilor mobile. Pe telefon, titlul are un rând complet, iar comenzile au un rând propriu. Mesajele, acțiunile și detaliile împart un singur container de derulare; headerul rămâne accesibil. Conținutul minimizat este limitat la 88px, iar half/expanded păstrează minimum 44px utili. Focusul unei acțiuni este readus în vedere la schimbarea stării și prin notificarea existentă `atlas-layout.onResize`, numai în fișa mobilă activă. Nu este introdus un ResizeObserver suplimentar.
5. **Meniul Mai multe.** Managerul închide panoul anterior și emite starea comună de overlay pentru meniu, backdrop și Escape. Harta și fișa acoperite devin inert; închiderea restaurează focusul la controlul vizibil.

## Regresii și acceptare

Regresiile permanente măsoară dreptunghiuri complete, nu numai centrele: comenzi/adnotări față de hartă, rail, card și preview, inclusiv intersecții între controale. Acoperă opt viewporturi obligatorii, stările fișei în șase dimensiuni compacte, card lung desktop la 900/1024/1440px cu panou deschis/închis, bootstrap mobil urmat de desktop/tabletă, ținte denumite minimum 44×44px, hit-test, titlu integral, scroll și focus după rotire, 30 Tab-uri sub overlay și toate cele 20 de niveluri de zoom. P6.2 folosește verificare geometrică pe ambele axe în locul presupunerii că scala trebuie întotdeauna să fie deasupra rail-ului.

Validare locală finală: 358/358 PASS, fără verificări omise, inclusiv P7.2 dedicat 14/14. Capturile efective au fost inspectate pentru toate cele opt viewporturi obligatorii și cazurile compacte/desktop suplimentare. Gate-urile GitHub, CodeQL, A/B și auditul Pages rămân de executat pe commitul publicat/integrat.

Acceptarea cere HEAD exact, toate required checks, CodeQL Actions/JavaScript și verificarea alertelor reale, A/B PASS fără mismatches, merge controlat fără bypass, audit Chrome/CDP pe deploymentul rezultat și comparație literală cu bloburile Git pentru resursele frontend și cele 123 de GeoJSON. Închiderea se documentează separat după aceste dovezi.

O singură hartă și aceleași selecții, filtre, cache, URL și History. Fără modificări de corpusuri, geometrii, identități, proveniență, manifeste, candidate lifecycle sau protecții. P7.3 începe numai după închiderea P7.2. Emularea Chrome nu reprezintă testare fizică Android/iOS sau certificare WCAG.
