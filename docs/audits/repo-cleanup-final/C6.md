# C6 — o singură execuție automată a suitei integrale

Stare la redactare: **LOCAL_VERIFIED_PENDING_CI**. Acceptarea ulterioară și SHA-urile exacte sunt în registrul de progres și raportul final. ACTUAL, dependențele, runnerul integral și setul său de teste sunt neschimbate.

Înainte, P8.2 și P8.4 executau separat aceeași comandă `node scripts/audit/p82-full-validation.mjs`, pe același commit. Cele două execuții observate în baseline au durat 814 și 894 de secunde numai pentru acel pas. Fiecare a executat 132 de fișiere de test, 1.074 de teste reușite și zero SKIPPED. Aceste durate sunt observații de timp runner, nu măsurători de CPU sau estimări de facturare.

| Verificare | Execuție automată după consolidare |
| --- | --- |
| Toți pașii vechi ai jobului frontend, inclusiv capturi și guard-uri | `browser-tests`, corp identic |
| Runnerul integral Linux, fără schimbarea codului sau a descoperirii testelor | `full-linux-regression`, o singură dată |
| Build topologie `--check` și cele trei teste de vecinătăți | `p82-derived-topology`, aceleași comenzi |
| Instalare offline, performanță export, surse și vendor GIS | `p84-export-validation`, aceleași comenzi |
| Contextul obligatoriu existent `frontend-browser-qa` | Rollup `if: always()`, acceptă numai succesul tuturor celor patru joburi |

Numele celor șase required checks și protecțiile GitHub nu se schimbă. Joburile de lucru rulează independent, astfel încât eșecul unui job nu împiedică executarea celorlalte suite. Rollup-ul respinge rezultate eșuate, anulate, omise, absente sau invalide; nu transformă teste neexecutate în succes. Cele 22 de regresii ale procesului CLI verifică inclusiv aceste cazuri și legarea rezultatelor reale din workflow.

Fișierele P8.2/P8.4 anterioare rămân reproducători independenți prin `workflow_dispatch`, cu corpurile joburilor originale păstrate. Execuțiile automate echivalente sunt în workflow-ul frontend; nicio condiție `skip-full-suite` nu este introdusă. Configurația explicită rămasă în reproducătorii manuali păstrează protocolul lor independent; runnerul și lista sa de descoperire au o singură implementare comună.

Capturile și artefactele frontend rămân neschimbate. Artefactul P8.4 țintit rămâne. Jobul integral salvează logul complet, lista exactă a fișierelor executate și eventualele rezultate `outputs/P8.4/`; păstrează retenția implicită a repository-ului, fără scurtarea contractului anterior P8.4. Nu este suficient numai statusul rollup-ului: acceptarea inspectează separat toate joburile, rezultatul complet al suitei și controalele post-merge.

`c6-coverage-proof.json` fixează hashul runnerului integral și hashul fiecărui fișier de test, identice cu baseline-ul C0. Comparația comenzilor demonstrează păstrarea tuturor comenzilor automate inițiale, cu singura reducere a celei de-a doua invocări identice a suitei integrale. `workflow-roles-registered.csv` distinge cele 80 de definiții Git curente de istoricul/definițiile altor branchuri păstrate în GitHub Actions. Stările workflow-urilor nu sunt activate sau dezactivate în această etapă.

Permisiunile rămân `contents: read`, versiunile și SHA-urile acțiunilor existente sunt păstrate, iar Ubuntu 24.04 și Node 24.21.0 rămân mediul testelor. Nu sunt modificate manifestele, sursele, identitățile, relațiile sau geometriile ACTUAL și nu este autorizat P9.1. Economia efectivă și verdictul se stabilesc din CI real al versiunii integrate, fără procente presupuse.
