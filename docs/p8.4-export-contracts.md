# Contractele P8.4 — atlas-export-v1

JSON: UTF-8, schemaVersion=atlas-export-v1. Entity metadata include entity, calculated
(null dacă nu există calcul validat în cache-ul P8.3), provenance. ID-urile sunt șiruri, nivelurile numere,
câmpurile indisponibile null. Identitatea juridică pozitivă se exportă numai când
statusul public este reconciled. hierarchy și roles rămân colecții explicite în JSON.
Nu se exportă bbox drept geometrie, cache, History, GPS sau starea internă.

GeoJSON individual: Feature WGS84 lon/lat, fără câmp crs depreciat. CRS explicit în
metadata/model; properties.sourceProperties păstrează proprietățile publice originale,
properties.atlas conține metadata aplicației, proveniență și atribuirea OSM/ODbL.
geometry este numeric identică cu sursa, fără schimbarea ordinii/preciziei/topologiei.
Serializarea JSON nu promite bytes identici cu FeatureCollection sursă.

CSV: UTF-8 cu BOM pentru Excel, separator virgulă, CRLF, toate celulele citate,
ghilimele dublate, lipsa reprezentată prin celulă goală. Antetul stabil entityColumns
este definit în atlas-export.mjs. Rolurile/ierarhiile complexe se păstrează în JSON.
Celulele text care încep cu formule (inclusiv după spații) primesc apostrof protector.
Codurile text numerice cu zero inițial sau minimum 15 cifre primesc același apostrof,
împiedicând conversia Excel în număr. La import programatic se elimină un apostrof
protector în aceste cazuri; apoi se aplică tipurile definite de coloane. Un număr
real negativ nu primește apostrof. CSV nu pretinde a fi fără adaptare pentru Excel.

Comparație JSON: identități A/B cu proveniențe separate, calculated, model și validation;
CSV folosește un rând cu id_a/id_b și unități în numele coloanelor, hashuri/snapshot.
Frontiera indisponibilă este null/goală și are motiv explicit. Numai rezultate complete
cu reziduuri în toleranța validată sunt exportabile. Geometriile derivate sunt evaluate:
P8.3 le validează, dar exportul lor este amânat pentru a nu adăuga formate/control suplimentar.
Nu intră în ACTUAL. P8.2 export listă evaluat și amânat; relațiile nu se agregă ambiguu.

Măsurare: JSON are kind=user-drawn-measurement, puncte numerice ordonate, geometry,
calculated și model. GeoJSON este LineString/Polygon; sursa user-drawn și osmData=false.
Se cere finalizare explicită; se refuză poligoanele invalide. Nu se transmit coordonate.
Model fix: sfera IUGG 6371008.8 m, arie pe laturi drepte lon/lat, lungimi cerc mare.

Vizual: SVG vectorial în proiecția și viewportul Leaflet curent, geometrii vizibile,
stiluri și evidențieri temporare; fără raster OSM, explicit în UI și document.
Atribuire, snapshot, dată UTC, limite WGS84, legendă și disclaimer cadastral incluse.
Print/PDF prin document izolat A4 portret/landscape, aspect ratio păstrat.
Textul de print este separat de scalarea hărții: 12pt titlu, 9pt legendă și surse.
PNG complet nu este oferit; SVG/PDF reprezintă alternativa fără CORS/tile download.
Scara metrică este omisă explicit din cauza variației Mercator cu latitudinea.
Straturile vectoriale nesuportate sau harta în animație opresc exportul cu mesaj.

Raportare: URL fix GitHub issues/new, template territorial-entity.md, parametri codificați.
Link entitate cu v=1 și e=id; fără vederea curentă/GPS/sesiune. Text copiabil și selectabil,
utilizatorul completează descrierea și trimite în GitHub. Fără API create-issue.

La comanda GeoJSON, citirea hash-bound este urmată de validarea topologică
P8.3 în Worker-ul GIS existent. Formatterul nu repară geometria; exportă numai
Feature-ul sursă validat. Calculele deja validate din cache pot fi incluse în
metadata JSON/CSV, fără recalculare la deschiderea exportului.
