## Metoda P9.0.7.2.18

`scripts/audit/p907218-osm-live-85.mjs` recitește fiecare relație individual prin **OSM API GET /api/0.6/relation/{id}/full**, nu doar `/relation/{id}`. Pentru fiecare obiect reconstruiește poligonul din toate way-urile `outer/inner` și nodurile lor, inclusiv inelele interioare, fără simplificare, decupare, snapping ori corectare. Compară **multisetul exact de segmente fără orientare** la șapte zecimale cu poligonul ACTUAL verificat deja față de PBF.

Se verifică separat versiunea și timestampul relației, hashul membrilor ordonați, tagurile exacte și versiunile/timestampurile way/node care compun conturul. Reconstructia se validează ca geometrie cu JSTS; numai dacă segmentele diferă se compară și egalitatea topologică DE-9IM. Orice diferență este raportată individual: numărul segmentelor adăugate/eliminate, schimbări de metadate/taguri, componente way/node editate după cutoff și clasificarea `UNCHANGED`, `METADATA_CHANGED_GEOMETRY_EQUAL`, `WAY_NODE_METADATA_CHANGED_GEOMETRY_EQUAL`, `SEGMENTS_CHANGED_TOPOLOGY_EQUAL` sau `GEOMETRY_CHANGED`.

**Dovadă recuperabilă:** arhivă GZIP fără pierderi cu fiecare răspuns XML `/full`, URL, fereastra de captură, SHA-256 XML, cardinalitate way/node, hashurile versiunilor componentelor și raport JSON per-ID. Cererile OSM sunt succesive; raportul declară explicit `atomic_snapshot=false`. Versiuni de relație neschimbate **nu** sunt considerate suficiente pentru a demonstra egalitatea poligonului.

**Gate separat:** `COMPLETE_85_UNCHANGED` numai dacă cele 85 de contururi, taguri, membri și componente way/node sunt neschimbate în raport cu cutoff. `COMPLETE_WITH_DIFFERENCES` înseamnă audit complet cu schimbări documentate, **nu** autorizarea vreunui refresh. `INCOMPLETE_SOURCE` dacă lipsesc XML, way/node sau alte probe, și jobul eșuează. Divergențele se examinează înainte de orice candidate distinct.
