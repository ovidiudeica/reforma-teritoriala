# P5.2 — Arbore Entități și vizibilitate explicită per-ID

Baseline: `main` post-P5.1 `db6544291cef9eb7170a3061c69f414cb22e4166`. Branch separat: `web/p5.2-entity-tree-visibility`.

## Limite și ordinea de implementare

1. **Etichete strict de prezentare:** `compactTreeName(node)` produce denumirea scurtă fără să schimbe `node.id`, `display_name`, parentage sau geometria. Primele exemple: România, Moldova, Cluj, UATSN, UTAG. Cardul selectat păstrează numele și metadatele oficiale.
2. **Rândul arborelui real:** trei controale independente — expand/collapse, checkbox geometric, buton nume pentru selecție. Fără badge-uri tehnice sau coduri în rând. Conservăm lazy rendering și identitatea de 5.848 ID-uri, inclusiv coalesced/statistical-only fără duplicări.
3. **Vizibilitate explicită:** `visibleEntityIds` pornește numai cu cele două ID-uri rădăcină RO/MD; fiecare alt ID este OFF. Extinderea, căutarea și selecția nu bifează copii. Aplicarea filtrelor globale este o intersecție cu acest set, nu modifică bifele.
4. **Hartă și URL:** adaptarea tuturor surselor de layer (overview, chunk local/detail, statistice separate) la predicatul unic per-ID și păstrarea politicii de zoom/lazy; orice serializare URL nouă trebuie să păstreze backward compatibility și Back/Forward.
5. **Regresii obligatorii:** unit tests, browser Chrome/CDP șapte viewporturi, URL/history, 5.848 × 170 matrice, geometrie/CodeQL/A-B. Nu se schimbă `data/`, `public/`, manifestele sau geometriile. P5.3 păstrează exclusiv panoul separat de filtre și toggle-ul fundalului OSM.

## Status al acestui increment

Modulul `atlas-tree-labels.mjs` și testul său sunt adăugate separat, fără a conecta încă schimbarea în UI. Astfel, regresiile P4 rămân normative până la implementarea atomică a rândului, checkboxului și predicatului de geometrie. **P5.2 este în curs, nu complet.**

## P5.2.1 — Arbore și geometrii per-ID
Rândul oferă disclosure, checkbox și selecție independentă. Setul inițial explicit conține numai cele două root IDs RO+MD; copiii nu moștenesc bifa. Straturile overview, local/detail, chunk-uri și statistice separate folosesc `visibleEntityIds.has(id) && geometryVisible(...)`. Filtrele globale pot ascunde o geometrie bifată fără să modifice bifele. URL v=1 este compatibil; parametrul repetabil x serializează diferențele XOR față de rădăcini. Căutarea și selecția nu activează geometrii. Datele și geometriile nu se modifică. Panoul separat de filtre și basemap toggle rămân P5.3.
