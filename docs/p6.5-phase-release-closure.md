## 2. Contractul vizual final: patru comenzi native Leaflet

Ordine verticală: **zoom +, zoom −, încadrare România+Moldova, fundal raster OSM**. Butoanele de încadrare și fundal sunt integrate în același `.leaflet-control-zoom`, folosesc iconuri SVG și targeturi tactile de minimum 44×44 px. Comutatorul OSM indică prin icon barat și `aria-pressed` dacă fundalul este oprit.

Bara nu modifică selecția, entitățile bifate, filtrele, geometriile ori datele. P6.4.3 mută scala pe mobile/tabletă sus-dreapta, sub atribuirea OSM, și butonul de restrângere a exploratorului pe desktop lângă bara de zoom. Regresia verifică centrul neobturat al **tuturor celor patru butoane** și inexistența intersecției cu scala; verificarea CDP a arătat 5/5 viewporturi reprezentative PASS pentru remedierea CSS (390×844, 844×390, 768×1024, 899×768, 1440×900). În lipsa unui viewport explicit din URL, încadrarea folosește `fitBounds` al celor două entități-rădăcină ACTUAL; linkurile cu lat/lon/z explicite rămân valabile. Parametrul `m=0`, Back/Forward și toggle-ul raster independent au fost testate.

**Chrome real/CDP contra GitHub Pages publicat**, P6.4.2: **8/8 teste PASS**, fără JavaScript exceptions, erori de asset proprii, obstacol la click sau overflow în cele opt viewporturi: 360×640, 390×844, 430×932, 844×390, 768×1024, 899×768, 900×768 și 1440×900. Cazuri testate: stări OSM ON/OFF și raster count, vectorii și selecțiile invariabile, `m=0` și Back/Forward, entitate selectată în landscape, zoom-home după OSM OFF, focus/Enter și explorer desktop colapsat.

Verificările de acceptare anterioare includ P6.4.1 **31/31 Chrome live** pe matricea P6.4.1 + regresii P5/P6 și P6.4 **8/8** audit dedicat local, documentate în PR-urile aferente. Nu însumăm suite executate pe commituri diferite ca și când ar fi o singură execuție.
