# Security policy

## Supported versions

Security fixes are applied to the current ACTUAL pipeline and web application on `main`. Published ACTUAL data releases remain immutable historical artifacts; a security fix that changes generated bytes is delivered through a new candidate/release rather than by rewriting an existing release.

## Reporting a vulnerability

Please use GitHub's private vulnerability reporting / Security Advisories for this repository when available. Do not open a public issue for a vulnerability that could expose repository credentials, release-integrity controls, or exploitable parser behavior.

Include the affected path/workflow, reproduction conditions, expected impact, and any relevant dependency/advisory identifiers.

## Supply-chain policy

- GitHub Actions are pinned to immutable commit SHAs.
- npm dependencies are lockfile-pinned and vendored for deterministic offline installation.
- Dependency refreshes must update `package-lock.json`, `vendor/npm/manifest.json`, and `vendor/npm/npm-dependency-bundle.tar` together.
- Networked source refresh is separated from deterministic candidate build and release gates.
